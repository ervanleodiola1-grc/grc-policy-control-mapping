# Project 2: GRC Policy-to-Control Mapping

A beginner GRC (Governance, Risk, and Compliance) project where I wrote three short security policies and mapped each section to the matching controls in the NIST Cybersecurity Framework (CSF) 2.0.

## Why I made this

I'm a student studying Criminology and Business Adminstration and wanted hands-on practice with GRC work. Mapping policies to a framework is a core GRC task, so I built a small example to learn how it works.

## What's inside

| Folder | Contents |
|---|---|
| `policies/` | Three policies I wrote: Password, Access Control, and Incident Response |
| `mapping/` | A table linking each policy section to a NIST CSF 2.0 control |

## How to read the mapping

Each row in the mapping table shows:

- **Policy section:** where the rule appears in my policy
- **Requirement:** what the rule says, in plain English
- **NIST CSF 2.0 control:** the framework requirement it supports
- **Notes:** why I think the two match

## What I learned

- I learned that policies in a GRC context is a lot more than a simple guideline but rather answer "what" must be done and "why", bridging governance with operational execution
- For NIST CSF, I had thought that it was legally enforced but it is completely voluntary unless specified by a government contract or regulation
- Last, the aspect that I found a lot harder to do than I expected was definetly trying to translate the intricate frameworks into an understanble language for both me and to who might view this repository.

## Limitations and next steps

This is a learning project, not a full compliance assessment. The policies are fictional and written for a made-up small company, and the mapping reflects my own interpretation as a beginner.

If I continue this project, I'd like to:

- Map the same policies to a second framework, such as ISO 27001 or CIS Controls
- Add a short risk register showing which risks each policy reduces
